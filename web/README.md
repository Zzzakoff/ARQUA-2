# Patch Review — веб-интерфейс интерактивного ревью

Django-приложение, реализующее веб-интерфейс для ручного ревью patch proposals по OpenAPI.

## Что реализовано в рамках пункта 5 ТЗ

- просмотр загруженных сканов OpenAPI;
- постраничный просмотр предложенных правок;
- фильтрация предложений по статусу;
- отображение обоснования правки;
- отображение источника истины и уровня уверенности;
- отображение признака обязательного ручного разбора;
- просмотр содержимого «до / после»;
- принятие и отклонение каждой правки отдельно;
- редактирование предлагаемого результата;
- роль `reviewer`: действия ревью доступны группе `reviewer` и суперпользователю;
- CSRF-защищённые POST-действия принятия и отклонения;
- фиксация пользователя и времени ревью;
- экспорт согласованных (принятых) изменений в JSON, Markdown, HTML и patch;
- пагинация очереди правок;
- адаптивный веб-интерфейс.

Форма ручного создания proposal оставлена как демонстрационный источник тестовых данных. В полном проекте такие proposals должны поступать от модулей статического/live-анализа из других пунктов ТЗ.

## Запуск Windows

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
py manage.py migrate
py manage.py seed_demo
py manage.py runserver
```

Откройте `http://127.0.0.1:8000/`.

## Создание пользователя-ревьюера

Самый простой вариант для демонстрации — создать суперпользователя:

```powershell
py manage.py createsuperuser
```

Либо создать обычного пользователя через Django Admin и добавить его в группу `reviewer`.

## Тесты

```powershell
py manage.py test
```

## Демонстрационный сценарий

1. Выполнить `py manage.py seed_demo`.
2. Войти под reviewer/superuser.
3. Открыть скан «Демо OpenAPI».
4. Создать тестовый proposal: `/users`, `GET`, `404`, «Пользователь не найден».
5. Раскрыть блок «до / после» и проверить предлагаемое изменение.
6. При необходимости нажать «Редактировать» и изменить итоговый OpenAPI.
7. Нажать «Принять» или «Отклонить».
8. Для принятых правок скачать JSON, Markdown, HTML или Patch.
