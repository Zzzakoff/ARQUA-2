# Проверки статического анализа маршрутов

Доработка пункта 1: исходная проверка тестов и покрытия,
воспроизведение пропущенных маршрутов, расширение их статического разбора.

## Результат

Анализатор теперь распознаёт:

- обычные и асинхронные обработчики (`def` и `async def`);
- строковый адрес первым аргументом и через `path="..."`;
- `api_route` с несколькими методами, заданными списком, кортежем или множеством строк;
- `api_route` без методов, с `methods=None` или пустой коллекцией как GET;
- несколько декораторов и повторное подключение роутера с разными префиксами.

Для каждого метода создаётся отдельный EndpointContract. Сохраняются параметры,
тело запроса, модель ответа, явно заданный числовой статус, теги, файл и строка
объявления. Исправлен разбор абсолютного импорта роутера: `from routes import router`
больше не превращается в ссылку на несуществующий модуль `main.routes`.

Вычисляемые адреса и списки методов не исполняются и не угадываются: объявление
пропускается с предупреждением. Тестовые приложения записываются во временные
каталоги pytest и анализируются как текст; запуск сервера и доступ к LLM не нужны.

## Запуск из корня проекта

Сначала установите проект с зависимостями разработки в виртуальное окружение:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
```

Все существующие и новые тесты с покрытием:

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
.\.venv\Scripts\python.exe -m coverage run --data-file=.venv/static-coverage --source=src/drift_agent -m pytest tests checks/static_analysis -q -p no:cacheprovider
.\.venv\Scripts\python.exe -m coverage report --data-file=.venv/static-coverage
.\.venv\Scripts\python.exe -m coverage json --data-file=.venv/static-coverage -o .venv/static-report.json
```

Только новые проверки:

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
.\.venv\Scripts\python.exe -m pytest checks/static_analysis -q -p no:cacheprovider
```

Обычный запуск pytest без указания каталогов по прежней конфигурации проекта
собирает только `tests`. Для новых проверок нужно явно указать `checks/static_analysis`.
