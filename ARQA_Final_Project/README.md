# ARQA — итоговый интегрированный проект

**Django Patch Review + статический анализ api-drift-agent + история SQLite + опциональная LLM + CI.**

## Что уже работает

- Загрузка ZIP-архива исходников **Python/FastAPI**, с отдельным OpenAPI 3.x файлом (`yaml`, `yml`, `json`) либо с OpenAPI внутри ZIP (предпочтительно `openapi.yaml`).
- Безопасная распаковка с проверкой путей, символических ссылок, целостности, количества и размера файлов. **Чужой код не исполняется**: анализатор читает Python через AST.
- Статическое сравнение OpenAPI и FastAPI: endpoints, параметры, схемы, коды HTTP-ответов, обязательность полей и другие категории, поддерживаемые веткой `4` анализатора.
- Сохранение оригинального ZIP, OpenAPI (если передан отдельно), результатов, SHA256 и статуса скана в SQLite + защищённом файловом хранилище `uploads/`.
- Просмотр находок, приоритетов и доказательств; фильтрация, пагинация, роли `reviewer`, принятие/отклонение/изменение правок, история и экспорты JSON/Markdown/HTML/patch.
- Сохранён **старый способ импорта** готового `drift-report.json` с опциональным OpenAPI.
- Опциональный LLM-режим: **Ollama локально или Groq через API**. Объяснение влияния изменений, рисков и рекомендаций. Модель не является источником обнаружения ошибок. Без модели статический анализ работает.
- Сохранены улучшенные классификатор, тестовые сценарии и CI-конфигурация веток команды.

## Установка на Windows / VS Code

Распакуйте итоговый ZIP. Откройте VS Code в папке, **где лежит `manage.py` и `requirements.txt`**.

В терминале PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver
```

Откройте **http://127.0.0.1:8000/**, войдите под созданным администратором и загрузите ZIP в верхнем блоке. Двойной клик по `START_WINDOWS.bat` тоже запускает сервер (создание администратора остаётся отдельной командой).

**Важно:** нужен Python 3.11+, доступ к PyPI для первой установки. Не запускайте `manage.py` из родительской папки.

Linux/macOS: `python3 -m venv .venv`, затем `.venv/bin/python -m pip install -r requirements.txt`, `migrate`, `createsuperuser`, `runserver`.

## Проверить анализ без LLM

1. Войдите под администратором.
2. Загрузите `demo/fastapi_demo.zip`. Файл `openapi.yaml` находится внутри архива; поле OpenAPI можно оставить пустым.
3. Отключите галочку LLM, нажмите «Анализировать проект».
4. Откроется скан с реальными результатами анализа; просмотрите категории и доказательства, примите или отклоните изменения и экспортируйте результат.
5. Альтернативно загрузите `demo/fastapi_demo_openapi.yaml` как отдельную спецификацию вместе с тем же ZIP.

## Настройка LLM

LLM опциональна и **по умолчанию выключена**. Если активировать:

- **Ollama**: установите Ollama на своём компьютере, выполните `ollama pull qwen2.5-coder:7b`. Выберите `Ollama` на сайте (модель можно изменить).
- **Groq**: получите API-ключ и задайте переменную окружения `GROQ_API_KEY`, например перед запуском в PowerShell: `$env:GROQ_API_KEY='ВАШ_КЛЮЧ'`. Выберите `Groq` и при необходимости введите название модели.
- За один запуск LLM объясняет **не более 15** находок. Внешний Groq получает фрагменты найденных ошибок и доказательств; не отправляйте секреты/конфиденциальные проекты в облачную модель. Проблемы API/модели фиксируются в статусе сканирования, сам статический отчёт остаётся доступным.
- Для составления объяснений используется LLM-клиент из интегрированного api-drift-agent. Отдельный запрос возвращает влияние, риски и рекомендацию. Ревьюер всё равно принимает окончательное решение.

## Данные и безопасность

- `db.sqlite3`: пользователи, сканирования, метаданные, находки, принятые решения и рекомендации.
- `uploads/private_projects/archives/`: загруженные ZIP. `uploads/private_projects/<id>/source/`: безопасно извлечённые файлы. `uploads/specifications/`: отдельно загруженные OpenAPI. `uploads/drift_reports/`: отчёты.
- Для ZIP-проектов просмотр результатов и скачивание файлов доступны только автору и администратору. ZIP-загрузка требует входа в аккаунт.
- ZIP проверяется до извлечения: <=30 МБ входной файл, <=100 МБ распакованного содержимого, <=1600 файлов, <=12 МБ на файл; запрещены абсолютные пути, `..` и symlinks. Динамическое выполнение проекта и отправка ZIP LLM не производятся.
- Настройки разработчика включены по умолчанию для **локальной** демонстрации. Перед публикацией задайте `DJANGO_DEBUG=0`, собственный `DJANGO_SECRET_KEY`, доверенные `DJANGO_ALLOWED_HOSTS`, HTTPS, лимиты запросов и отдельное изолированное хранилище. Не публикуйте `uploads`, SQLite и ключи.

## Разграничение готового и будущего

- Включён **статический FastAPI-анализ**, не анализ запущенного API по HTTP (live-probing пока нет).
- Экспорт `patch` в старом UI преимущественно содержит **рекомендации**, а не всегда применимый `git apply` diff. Автоматическое изменение исходного кода или спецификации **не выполняется**.
- LLM объясняет на основании результатов анализатора и может ошибаться; рекомендация не является подтверждением совместимости.
- В MVP запуск анализатора и LLM **синхронный** и ограничен по размеру; для многопользовательского продакшена понадобится очередь фоновых заданий, таймауты и дополнительная изоляция.
- Структура ZIP должна содержать FastAPI Python-исходники; языки C#/Java/Django не поддерживаются этим статическим анализатором.

## Объединение веток

Основа интерфейса — `patch_review_integrated_api_drift`. Анализатор и классификатор — `ARQUA-2-4`, сохранены фикстуры из `ARQUA-2-main`. CI workflow и скрипт — `ARQUA-2-ci-integration`. Изменения Django находятся в `reviewer/services`, `reviewer/forms.py`, `reviewer/views.py`, `reviewer/models.py`, миграции `0004` и шаблонах.
